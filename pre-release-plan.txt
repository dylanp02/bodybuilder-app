-------------------------------------------------------------------
TECH STACK
-------------------------------------------------------------------
- Framework:      React Native via Expo SDK 54
- Routing:        Expo Router v6 (file-based, Stack + Tabs)
- Language:       TypeScript (strict)
- Backend:        Supabase (Postgres + Auth + RLS + Edge Functions)
- Styling:        React Native StyleSheet, dynamic dark/light theme
                  via React Context (useColors + makeStyles pattern)
- State:          useState / useContext — no external state library
- Navigation:     expo-router (router.push / router.replace)
- Notifications:  expo-notifications (local only; push stubbed)
- Storage:        AsyncStorage (prefs, session flags)
- Charts:         Custom LineChart component (components/LineChart.tsx)
- Pro gating:     Single compile-time flag in lib/proAccess.ts
                  (DEV_PRO_UNLOCKED: boolean)
- Payments:       Subscription UI only — no payment SDK integrated yet
- Build:          Currently Expo Go only — no EAS build exists yet

SUPABASE SCHEMA (current tables)
-------------------------------------------------------------------
profiles
  id uuid (FK auth.users)
  username text NOT NULL
  full_name text
  height_inches numeric
  weight_lbs numeric
  goal text
  experience_level text
  onboarding_complete boolean DEFAULT false
  ** NEEDS: is_pro boolean DEFAULT false
  ** NEEDS: push_token text

workouts
  id uuid PK
  user_id uuid FK
  name text
  date date
  created_at timestamptz

workout_sets
  id uuid PK
  workout_id uuid FK
  exercise_id uuid FK
  set_number int
  reps int
  weight_lbs numeric

exercises
  id uuid PK
  name text
  muscle_group text
  equipment text
  is_compound boolean
  notes text
  ** NOTE: currently SHARED across all users (no user_id)
  ** DECISION NEEDED: keep as shared library or make user-scoped?

weight_logs
  id uuid PK
  user_id uuid FK
  date date
  weight_lbs numeric

measurements
  id uuid PK
  user_id uuid FK
  date date
  neck_in, chest_in, shoulders_in, biceps_in, forearms_in,
  thighs_in, calves_in, waist_in, hips_in (all numeric nullable)
  UNIQUE(user_id, date)

workout_templates
  id uuid PK
  user_id uuid FK
  name text
  exercises jsonb  -- array of TemplateExerciseData objects
  created_at timestamptz

training_plans
  id uuid PK
  user_id uuid FK
  plan_type text ('weekly' | 'cycle')
  plan_name text
  duration_weeks int
  start_date date
  schedule jsonb
  is_active boolean DEFAULT true
  created_at, updated_at timestamptz
  UNIQUE INDEX: one active plan per user

All tables: RLS enabled. Policies restrict all operations to
auth.uid() = user_id. exercises table is shared (no user_id filter).

PHASE 1 — PRO SUBSCRIPTION (PAYMENTS + RUNTIME GATING)
--------------------------------------------------------
Recommended approach: RevenueCat
  - Abstracts Apple StoreKit + Google Play Billing
  - Handles receipt validation, webhooks, subscription lifecycle
  - Provides dashboard for subscription metrics
  - react-native-purchases SDK

Steps:

1. RevenueCat dashboard:
   - Create project, connect App Store + Google Play
   - Create Entitlement: "pro"
   - Create 3 Products (monthly, biannual, yearly) per platform
   - Create Offering containing all 3 Packages

2. App Store Connect:
   - Create 3 auto-renewable subscription products with matching SKUs
   - Configure subscription group

3. Google Play Console:
   - Create 3 subscription products with matching product IDs

4. Install react-native-purchases (requires dev build):
   import Purchases from 'react-native-purchases';
   - Initialize on app launch with Supabase user UID as app user ID
     so purchases are tied to the account across devices

5. Supabase:
   - ALTER TABLE profiles ADD COLUMN is_pro boolean NOT NULL DEFAULT false;
   - Create Edge Function: /functions/v1/revenuecat-webhook
     Validates RevenueCat shared secret, updates profiles.is_pro
     on events: INITIAL_PURCHASE, RENEWAL, CANCELLATION,
     EXPIRATION, REFUND, BILLING_ISSUE_DETECTED

6. Runtime ProContext (replaces compile-time flag):
   - Create lib/ProContext.tsx providing isPro: boolean
   - In _layout.tsx, alongside the onboarding check, also fetch
     profiles.is_pro and cache it in the context
   - Re-check on foreground resume (AppState change)
   - DEV_PRO_UNLOCKED in lib/proAccess.ts remains as a dev override
     that short-circuits the context check to true
   - ProBanner and all gate checks read useProContext().isPro
     instead of DEV_PRO_UNLOCKED directly

7. Subscription screen:
   - Fetch current Offerings from RevenueCat on mount
   - Wire Subscribe buttons to Purchases.purchasePackage(pkg)
   - Show current plan + next renewal date if already subscribed
   - Add "Restore Purchases" button (required by App Store guidelines)
   - Handle errors: user cancelled, billing unavailable, network error

PHASE 2 — PUSH NOTIFICATIONS
------------------------------
expo-notifications is installed. Local scheduling works once
running outside Expo Go. Push (server-triggered) is not wired.

Tasks:

1. On app launch (dev build): call requestNotificationPermission()
   already in lib/notifications.ts — this will work in dev build

2. Retrieve push token:
   const token = await Notifications.getExpoPushTokenAsync();
   Store in profiles.push_token (add column to schema)
   Re-store on every launch (tokens can rotate)

3. Server-side triggers (Supabase Edge Functions or cron):
   - Bodyweight reminder:
     Cron job: find users where last weight_logs.date < now - 5 days
     AND notif prefs deviceEnabled = true AND deviceMuted = false
     Send push via Expo Push API or APNs/FCM directly
   - Training day reminder:
     Read active training_plan, compute today's day type
     Send morning + afternoon pushes on training days,
     morning only on rest days

4. Deep link on notification tap:
   Set notification data.url to the target route
   Handle in Linking listener already in _layout.tsx

5. Android notification channel:
   Already created in lib/notifications.ts as
   'bodybuilderapp-reminders' — verify it fires in dev build

OPEN DECISIONS (need answers before implementation)
-------------------------------------------------------------------
1. RevenueCat vs direct StoreKit/Play Billing?
   RevenueCat recommended — saves significant implementation time.
   Costs ~$0/month under 10k MTR, then $119/month.

2. Free trial?
   Apple and Google both support free trials on subscriptions.
   7-day trial on yearly plan is a common conversion driver.
   Must be decided before creating products in the stores.

3. exercises table — shared or user-scoped?
   Currently all users share the exercise library. Custom exercises
   created by one user are visible to all. Decide:
     Option A: Keep shared (community library) — simpler, no change
     Option B: Add user_id, make exercises user-scoped — breaking
               schema change, requires data migration

4. Email notifications in v1.0?
   The mute/enable toggle exists in the UI but email sending is
   stubbed (sendEmailBodyweightReminder etc. in lib/notifications.ts
   do nothing). If not in scope for v1.0, remove the toggle from
   the UI before submission to avoid user confusion.

5. Crash reporting service?
   Sentry is free up to 5k errors/month. Must be added before
   real users — near-impossible to retrofit cleanly post-launch.
